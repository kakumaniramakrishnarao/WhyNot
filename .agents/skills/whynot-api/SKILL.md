# Working on the WhyNot API

Spec: `docs/05-api-and-data.md`, `docs/01-architecture.md`.

## Route checklist

- [ ] Request and response schemas come from `@whynot/contracts/api` (add them there first). Validate both in dev/test.
- [ ] Read demo role from `X-Demo-Role` / `X-Demo-Patient`; reject unknown patient IDs with 400.
- [ ] Anything returned to a patient passes through `projectForAudience(evaluation, 'patient')`. Staff-only routes check role = staff (403 otherwise).
- [ ] `now` comes from the demo clock helper (`getNow()`), never `new Date()` directly in route logic.
- [ ] Errors use `{ error: { code, message, details? } }` with correct status codes.
- [ ] Log one structured line per request; never log patient names, request bodies with names, or narration text.
- [ ] Integration test for success, validation error, and the main failure path.

## Data rules

- Migrations are generated by drizzle-kit and committed; never edit a migration that has been merged — add a new one.
- Policy versions are immutable; "editing" a policy creates a new version and switches `is_active` in one transaction.
- Bookings: cancel = status change + `cancelled_at`; never delete.
- Booking creation: SERIALIZABLE transaction → load snapshot inside the transaction → `evaluate` → insert or 409 with projected evaluation; retry serialization failures up to 3 times.
- Snapshot loader loads only the needed window (doc 05) and returns contract-validated `ClinicSnapshot`.

## Security basics

Input size limits (body ≤ 16 KB), rate limits on `/explain`, `/narrate`, `/bookings`, `/demo/reset`; CORS restricted to the web origin; secrets only from env; `.env.example` lists every variable with a comment.
